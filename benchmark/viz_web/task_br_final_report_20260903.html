一个三格小例子

目标货架 A 想到达中间格，但挡路货架（blocker）B 正占着那里，右侧 只有一个空格。新的引导信息不会直接派机器人去等 A；它先编译出依赖， 并只派发当前真能做的叶子任务。

Task-BR-PIBT 编译出的因果关系

A：左 → 中 依赖 B：中 → 右（Ready）

机器人分配表 ρ（rho）只把机器人分给绿色的立即可 执行任务（Ready task）。B 移完后，货架布局发生变化，系统基于 新布局开启下一轮（upper epoch），A 的一步任务才变成 Ready。 这样机器人不会提前去一个尚不能 Lift/Move 的任务前长期等待。

拥挤与宽松盘面的区别：货架刚走完一步后，如果新任务 恰好要求原路返回，宽松盘面不会自动续上连续搬运绑定（custody）， 避免两格震荡；目标货架相对空格很多的拥挤盘面（target-dense）允许 直接绑定，以免极少空格时丢掉必要的连续搬运。这里的精确定义是 n_targets > n_vacancies 且 n_targets - n_vacancies >= n_vacancies。 n_targets 是目标货架数，n_vacancies 是上层空格数。反向 Move 在两种盘面中都仍由物理搜索树枚举。
候选怎么避免来回折腾：先比较所有目标任务的合计剩余 距离（aggregate residual）。合计相同时，只有一个空格就优先完成 高优先级目标任务；有至少两个空格时，再逐个比较每个目标任务的完整 剩余距离。前者让单空位“接力搬运”不断链，后者阻止宽松盘面为了 低优任务把刚清开的挡路货架搬回去。

一分钟术语表

  • upper epoch：上层货架位置不变的一段时间； loaded Move 改变货架位置时开启下一轮。
  • root：一个目标货架当前“去哪个目标格”的使命； blocker task 会继承请求它让路的 root。
  • τ（tau）：目标货架到临时目标格的匹配； ρ（rho）：空闲机器人到当前 Ready task 的匹配。
  • custody：机器人正搬着某个货架，并绑定到一个 exact one-step task 的状态。
  • makespan：整份计划完成所需的总时间步； weighted SOC：所有机器人/货架动作成本的加权总和。 两者都是越小越好。
完备性边界：SearchKey 仍只含真实 robot/shelf configuration；临时目标、priority、task、rho 和 cache 都不进入 key。 operator constraint tree 最终仍枚举 primitive joint actions， apply_ops() 独立验证 successor。

最终实现做了什么

修改集中在原 attach_carrier_guidance() 及其直接消费的 Carrier-PIBT 数据，没有增加平行 planner 或第二套 search loop。
